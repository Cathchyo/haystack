# 森林扰动智能解译周报系统 PRD

> 版本：V0.1（MVP 草案）  
> 日期：2026-09-24  
> 输出形式：Markdown  
> 文档状态：需求初步明确，部分数据口径待核验

## 1. 产品概述

### 1.1 背景

项目上游通过卫星遥感影像和 SCCD 等算法识别森林扰动，并将处理结果输出为 SHP 矢量数据。本系统不直接处理原始卫星影像，也不使用视觉大模型，而是解析矢量数据中的图斑、属性和空间位置，结合森林扰动相关知识库，自动生成面向非遥感专业管理人员的森林扰动监测周报。

当前监测范围包括以下 5 个区域，后续计划扩展至全国：

- 大兴安岭
- 四川盆地
- 云南高原
- 湘中盆地
- 长江平原

区域清单应采用配置管理，不在程序中写死。

### 1.2 核心问题

系统重点回答：

> 本周哪些区域出现了什么森林扰动，数量和面积是多少，哪些变化最值得关注？

重点关注三类扰动：

- 采伐或人为清除（`Logging`）
- 森林火灾（`Wildfire`）
- 植被胁迫（`Stress`）

其中，植被胁迫可能与虫害、病害、干旱等因素有关。在没有额外证据时，系统不得直接将其表述为“虫灾”。

## 2. 产品目标

### 2.1 MVP 目标

1. 每个报告周期接收一批森林扰动 SHP 文件。
2. 自动提取图斑的类型、状态、时间、区域、面积、位置和变化分数。
3. 基于 `epoch` 初步识别本期批次的扰动记录。
4. 分别统计新增候选扰动和新增确认扰动。
5. 按区域和扰动类型生成客观、易读的 Markdown 周报。
6. 所有数字由程序计算，大语言模型只负责组织和解释已有事实。

### 2.2 非目标

第一版不包含：

- 原始卫星影像解译或视觉模型识别。
- 自动判定火灾、采伐或植被胁迫类型。
- 自动给出“轻微、一般、严重”等主观等级。
- 自动认定非法采伐、真实火灾或具体虫害。
- 自动发布周报及人工审核工作流。
- 全国范围的大规模生产部署。
- 地图图片自动生成。

## 3. 目标用户与使用场景

### 3.1 目标用户

主要用户为政府管理人员及其他不具备遥感专业背景的业务人员。

### 3.2 典型场景

每周新一批遥感处理数据到达后，业务人员运行系统。系统完成数据校验、统计和文本生成，输出一份 Markdown 周报，供管理人员快速了解本期森林扰动情况。

## 4. 业务对象与状态定义

### 4.1 扰动对象

一条扰动对象对应 SHP 中的一个矢量图斑。图斑表示一片被算法识别为可能发生森林变化的区域。

### 4.2 图层与算法状态

当前三个图层不是三个互斥状态：

| 图层 | 算法状态 | 含义 | 报告措辞 |
|---|---|---|---|
| `slgr_confirm` | 算法已确认 | 图斑内像元的连续异常观测数均值 `conse_last >= 6`，且扰动概率大于 `0.5` | “算法确认扰动” |
| `slgr_detected` | 未确认候选 | 满足扰动概率条件，但 `conse_last < 6`，等待后续有效观测确认 | “未确认候选扰动”或“疑似扰动” |
| `slgr_detected_rec` | 未确认候选（近期子集） | `slgr_detected` 中按上游“近期”规则筛选出的子集 | “近期未确认候选扰动” |

因此，`slgr_detected_rec` 不是第三种独立状态，也不能和 `slgr_detected` 全量相加。统计时必须明确使用“全部未确认候选”还是“近期未确认候选”。

这里的“确认”仅指算法确认，不代表人工审核或现场核实。`slgr_detected_rec` 的近期分界日期和筛选规则由上游批次定义，不能固定写死为界面示例中的日期。

### 4.3 扰动类型

| 原始类型 | 中文名称 | 未确认记录的推荐措辞 |
|---|---|---|
| `logging` | 采伐或人为清除 | 疑似采伐或人为清除 |
| `wildfire` | 森林火灾 | 疑似森林火灾 |
| `stress` | 植被胁迫 | 疑似植被胁迫 |

类型映射应配置化，并兼容原始值的大小写差异。未知类型不得强制归入以上三类，应计入“其他/未知”并在数据质量提示中列出。

## 5. 输入数据

### 5.1 矢量文件

当前样例包含三组图层：

- `slgr_confirm`：算法已确认扰动。
- `slgr_detected`：尚未确认的候选扰动记录。
- `slgr_detected_rec`：`slgr_detected` 的近期子集。

详细定义和数据质量规则见[数据图层语义](./01-data-layer-semantics.md)。

每组 Shapefile 至少需要完整提供 `.shp`、`.shx`、`.dbf` 和 `.prj` 文件；如存在 `.cpg`，也应一并读取以确定字符编码。

系统不得只根据文件名永久判断业务状态，图层名称与状态的映射应可配置。

### 5.2 已知字段

| 字段 | 用途 |
|---|---|
| `brightness` | 图斑相对正常状态的亮度变化分量 |
| `greenness` | 图斑相对正常状态的植被绿度变化分量 |
| `wetness_ch` | 图斑相对正常状态的湿度变化方向和幅度 |
| `disturbanc` / `disturbance` | 综合偏离正常状态的变化分数 |
| `detection` | 系统首次登记该扰动的日期 |
| `last_clear` | 最近一次有效、清晰的遥感观测日期 |
| `disturba_1` | 算法估计的扰动发生日期 |
| `epoch` | 对象生成或确认时对应的增量处理批次 |
| `agent` | 扰动类型 |
| `province` | 所属监测区域 |
| geometry | 图斑形状，用于计算面积、中心点和空间位置 |

字段名存在 Shapefile 截断风险，例如 `disturbanc`。系统应通过字段映射配置兼容实际名称。

### 5.3 后续需要补充的字段

- 稳定且跨批次不变的扰动对象唯一 ID。
- 明确的确认日期或确认批次字段。
- 更细粒度的行政区或林场名称（如业务需要）。
- 上游数据版本、生成时间和近期分界日期。

### 5.4 知识库资料

第一版需要逐步建立以下知识库：

- 三类扰动的定义及规范措辞。
- 字段含义和数据口径说明。
- 监测区域名称、层级和基础介绍。
- 扰动确认规则与 `epoch` 业务含义。
- 周报写作规范和免责声明。
- 经业务确认的历史周报样例。

知识库主要用于约束语言模型的解释和措辞，不负责替代空间计算或事实统计。

## 6. 本期数据判定规则

### 6.1 MVP 默认规则

在上游口径尚未完全确认前，MVP 暂按以下方式运行：

1. 每次运行显式指定一个或多个 `report_epoch`。
2. 图斑的 `epoch` 属于 `report_epoch` 时，计入“本期批次记录”。
3. 位于 `slgr_detected` 的本期记录，按报告口径计入“本期未确认候选扰动”；如报告只关注近期记录，则改用其子集 `slgr_detected_rec`。
4. 位于 `slgr_confirm` 的本期记录，暂计入“本期算法确认扰动”，不能表述为人工确认。
5. 报告同时记录本期使用的 `epoch`、数据生成日期和近期分界日期。

### 6.2 口径保护

在确认 `epoch` 确实分别代表候选生成批次和确认批次之前，周报标题及正文应优先使用“本期批次记录”，不得无条件宣称为严格意义上的“本周新增”。“本期新增确认”应理解为本期出现的算法确认记录，除非存在跨批次稳定 ID 和快照差分依据。

如未来获得稳定唯一 ID，可通过相邻两期快照对比确认：

- 新出现的候选扰动。
- 从未确认转为已确认的扰动。
- 类型或属性发生变化的扰动。
- 长期未确认且仍然存在的扰动。

## 7. 核心处理流程

```text
每周 SHP 数据与批次配置
          ↓
文件完整性、编码、坐标系和字段校验
          ↓
解析图斑属性，统一日期、区域和类型名称
          ↓
按 epoch 和确认状态筛选本期记录
          ↓
计算面积、中心点及分区域/分类型统计
          ↓
生成不可变的结构化事实数据
          ↓
检索知识库中的字段解释和写作规则
          ↓
大语言模型生成周报文字
          ↓
程序复核数字、类型和区域名称
          ↓
输出 Markdown 周报
```

核心原则：**程序负责计算事实，大语言模型负责表达事实。** 原始 SHP 不直接交给大语言模型。

## 8. 功能需求

### FR-01 数据导入与校验（P0）

- 支持读取每个图层对应的一组 Shapefile 文件。
- 检查必要伴随文件、坐标系、字符编码、空几何和无效几何。
- 检查 `epoch`、`agent`、`province` 及日期字段是否存在。
- 字段缺失或数据不可解析时停止生成，并输出明确错误。
- 非关键字段缺失时允许继续，但必须在报告的数据质量说明中提示。

### FR-02 空间与属性标准化（P0）

- 将日期统一为 `YYYY-MM-DD`。
- 将类型值统一映射为采伐或人为清除、森林火灾、植被胁迫。
- 计算图斑面积，统一使用公顷，并可附带平方千米。
- 面积计算必须基于适合的投影坐标系，不能直接使用经纬度单位计算。
- 提取图斑中心点坐标；第一版位置至少展示所属区域。

### FR-03 本期记录筛选（P0）

- 支持由用户选择或配置 `report_epoch`。
- 分开统计本期新增候选扰动和本期新增确认扰动。
- 记录并展示本次筛选口径。
- 当 `epoch` 为空或类型不一致时，将记录放入异常数据清单，不得静默丢弃。

### FR-04 统计分析（P0）

系统至少生成以下确定性统计结果：

- 图斑总数和总面积。
- 按确认状态统计数量和面积。
- 按三类扰动统计数量、面积和占比。
- 按 5 个区域统计数量、面积和占比。
- 各类型在不同区域的分布。
- 按面积和 `disturbanc` 分数排序的重点图斑。
- 零记录类型的明确结果。

第一版不将 `disturbanc` 自动转换为轻微、一般或严重等级。

### FR-05 知识库检索（P0）

- 根据本期出现的类型、区域和字段检索相关资料。
- 检索结果必须带来源和版本信息。
- 知识库没有依据时，模型不得补充具体成因、风险等级或处置结论。

### FR-06 周报生成（P0）

- 使用固定模板生成 Markdown。
- 使用面向非遥感专业人员的简洁语言。
- 明确区分“已确认”和“疑似/未确认”。
- 不将疑似采伐描述为非法采伐。
- 不将植被胁迫直接解释为虫灾。
- 某类型为零时，应表述为“本期数据中未发现相关记录”，不得写成“该区域不存在此类扰动”。

### FR-07 事实一致性检查（P0）

- 报告中的数量、面积、占比、日期和区域名必须能在结构化统计结果中找到。
- 程序在模型生成后重新检查所有关键数字。
- 检查失败时不得输出正式周报，应返回待修正草稿和错误说明。

### FR-08 结果留档（P1）

- 保存报告所用文件清单、数据批次、参数、事实统计和最终 Markdown。
- 建议输出文件名：`森林扰动监测周报_开始日期_结束日期.md`。
- 同一输入和配置应可重复生成一致的统计数字。

## 9. 周报结构

第一版只包含两个主体部分。

```markdown
# YYYY-MM-DD—YYYY-MM-DD 森林扰动监测周报

> 监测范围：...
> 数据批次：epoch=...
> 统计口径：...
> 数据状态：已确认/未确认说明

## 一、本期总体概况

- 本期新增候选扰动数量与面积
- 本期新增确认扰动数量与面积
- 三类扰动总体构成
- 主要分布区域
- 面积较大或变化分数较高的重点图斑

## 二、分类情况

### 1. 采伐或人为清除
- 数量、面积、确认状态、主要区域和重点图斑

### 2. 森林火灾
- 数量、面积、确认状态、主要区域和重点图斑

### 3. 植被胁迫
- 数量、面积、确认状态、主要区域和重点图斑

## 数据口径与限制
- epoch、近期分界日期、未确认数据及其他必要说明
```

第一版不要求生成地图；统计表可直接使用 Markdown 表格。重点图斑默认展示前 5 条，数量应可配置。

## 10. 语言模型输入与约束

语言模型只接收以下信息：

- 已由程序计算完成的结构化事实。
- 本期统计口径和数据质量提示。
- 知识库中检索到的相关定义与写作规则。
- 固定的周报 Markdown 模板。

模型必须遵守：

1. 不重新计算面积、占比或数量。
2. 不推断 SHP 中不存在的原因、损失或处置结果。
3. 不把未确认记录写成已确认事实。
4. 不把相关性描述为因果关系。
5. 不使用“严重”等缺乏规则支撑的评级词。
6. 对数据不足之处使用明确的限制性措辞。

## 11. 非功能需求

### 11.1 准确性

- 关键统计数字与程序计算结果保持一致。
- 面积展示默认保留两位小数，占比默认保留一位小数。
- 分项合计因四舍五入产生尾差时应主动说明。

### 11.2 可追溯性

- 每篇周报能够追溯到输入文件、`epoch`、参数、生成时间和知识库版本。
- 重点图斑应能回溯到源记录；在缺少唯一 ID 时至少保留源图层、源记录序号和几何指纹。

### 11.3 可扩展性

- 区域、图层、字段和类型映射均采用配置管理。
- 面向全国扩展时，可以替换区域字典和空间索引，而不修改周报生成逻辑。

### 11.4 数据安全

- 默认只向语言模型传递必要的聚合统计和经过筛选的重点图斑信息，不传递完整 SHP 文件。
- 是否允许调用外部云端大模型，需要在部署前由数据管理方确认。

## 12. 验收标准

满足以下条件即可认为 MVP 通过验收：

1. 能完整读取一批有效的三类 SHP 图层，并识别其状态。
2. 能按照指定 `epoch` 筛选本期记录。
3. 能正确输出数量、面积、占比、类型和区域统计。
4. 三种扰动类型均在报告中出现；无记录时给出正确的零值说明。
5. 报告能够区分新增候选扰动与新增确认扰动。
6. 报告不包含程序事实数据之外的数字。
7. 报告不把未确认事件表述为已确认事件。
8. 输出是结构完整、可直接阅读的 Markdown 文件。
9. 抽查报告中的数字，均可回溯到结构化统计结果和源图斑。
10. 输入字段或坐标系异常时，系统能明确报错，不生成误导性周报。

## 13. 待确认事项与风险

| 优先级 | 事项 | 影响与处理方式 |
|---|---|---|
| 高 | `epoch` 是否能准确代表候选生成批次和确认批次 | 未核验前使用“本期批次记录”措辞；上线前需由上游开发或数据负责人确认 |
| 高 | 是否存在跨批次稳定的扰动唯一 ID | 决定能否准确识别状态迁移和去重；需尽快补充 |
| 高 | 三个 SHP 图层是否每期都是完整快照 | 决定采用 `epoch` 筛选还是相邻快照差分 |
| 中 | 近期未确认分界日期的计算规则 | MVP 先作为每批次配置，后续对接上游元数据 |
| 中 | `agent` 的完整枚举值及含义 | 使用可配置映射，未知值单独报告 |
| 中 | 面向全国时采用的行政区层级 | 当前仅按 5 个监测区域统计，后续再扩展省/市/县或林场层级 |
| 中 | 大模型部署方式及数据安全要求 | 在选择云端或本地模型前确认 |

## 14. 建议实施顺序

1. 核验三个图层、字段、`epoch` 和唯一 ID 的真实语义。
2. 完成 SHP 解析、标准化、面积计算和确定性统计。
3. 固化一份结构化事实数据格式，并用现有样例进行人工核对。
4. 建立最小知识库和周报模板。
5. 接入大语言模型生成 Markdown，并增加事实一致性检查。
6. 使用连续两期真实数据验证“新增候选”和“新增确认”口径。
