# 森林扰动知识库规范

> 版本：1.0  
> 更新日期：2026-09-25  
> 状态：初稿

## 文档目的

规定知识库应保存哪些稳定的专业背景，以及大模型可以如何使用这些知识。知识库用于帮助模型正确解释术语，不能替代本期数据或推测缺失事实。

## 一、知识库内容

第一版只建立以下四类知识：

| 类别 | 主要内容 | 当前状态 |
|---|---|---|
| 扰动类型 | 采伐、森林火灾、植被胁迫的定义和解释边界 | 部分已有 |
| 遥感指标 | `brightness`、`greenness`、`wetness_ch`、`disturbanc` 等字段含义 | 已有初稿 |
| 区域字典 | `province` 区域代码、中文名称及层级 | `[待补充]` |
| 业务术语 | 算法确认、未确认候选、本期新增、历史记录等标准表述 | 已有初稿 |

建议按以下结构维护：

```text
knowledge-base/
├── disturbance-types.md
├── remote-sensing-indicators.md
├── regions.md
└── terminology.md
```

## 二、知识库边界

### 可以保存

- 经确认的术语定义和字段解释。
- 区域代码与规范名称的映射。
- 经业务确认的分类标准和专业解释。
- 有明确来源的行业标准或政策文件。

### 不应保存

- 本期图斑、数量、面积等动态事实。
- 原始 SHP、完整几何或本期统计结果。
- 未确认的灾害原因、损失和处置结论。
- 将植被胁迫直接等同于虫灾的推断。
- 仅供模仿文风的历史周报；此类材料应单独作为写作样例管理。

分类规则、统计规则和周报模板属于系统强制规则，应始终生效，不能作为可能检索不到的知识库内容。

## 三、大模型使用规则

大模型生成周报时，信息优先级为：

```text
结构化事实数据 > 已审核知识库 > 不输出
```

大模型可以使用知识库：

- 解释专业字段和扰动类型。
- 将区域代码转换为规范名称。
- 使用统一、易懂的业务措辞。
- 说明数据和算法的适用边界。

大模型不得使用知识库：

- 增加本期数据中不存在的事件或数字。
- 推断扰动的具体成因、严重程度或经济损失。
- 用历史资料替代本期事实。
- 在知识缺失时依靠模型自身知识补充业务结论。

## 四、知识条目要求

每份知识文档至少记录：

```text
id: [KNOWLEDGE_ID]
title: [TITLE]
version: [VERSION]
status: draft | approved
source: [SOURCE]
reviewed_at: [DATE]
content: [CONTENT]
```

只有 `approved` 状态的内容可以进入正式周报生成流程。系统应记录每次生成周报时使用的知识条目 ID 和版本，便于追溯。

## 五、第一版使用方式

第一版知识量较少，可根据扰动类型、区域代码和字段名称直接选择相关条目，不要求立即建设复杂的向量检索系统。

生成流程为：

```text
结构化事实数据
        +
按类型/区域选中的知识条目
        +
固定周报模板与写作规则
        ↓
大模型生成 Markdown 周报
```

知识库找不到对应内容时，保留客观数据并省略专业扩展解释。
